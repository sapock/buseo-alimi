## 0. 확정 사항 요약

| 항목 | 결정 |
|---|---|
| 실행 위치 | **공유PC (Windows), Windows 서비스** — merge-master 에이전트와 같은 PC |
| 언어·스택 | Go(백엔드) + React·TypeScript·Vite(프론트) + SQLite, **실행 파일 하나** |
| 접속 | 부서원은 브라우저로 `http://<공유PC IP>:8070` |
| 로그인 | 접속 IP로 식별 → 명단에 없으면 ID 입력(승인 없음) |
| 권한 | 관리자 / 부서원 두 가지. 누구나 글쓰기, 자기 글만 수정 |
| 응답 | Todo만 '완료했어요'. 공지는 응답 없음 |
| 전체 대상 | 나중에 들어온 부서원 포함, 글이 완료되면 대상자 고정 |
| 백업 | 완료된 글마다 폴더 하나(`post.json` + 이미지) + 매일 DB 사본 |
| 규모 | 부서원 약 60명, 글 월 10~15건 |

### 공유PC로 정하면서 생긴 이점
- merge-master 에이전트가 **같은 PC**(`:8090`)에 있어서, 알리미가 `http://127.0.0.1:8090/api/sessions`를 바로 조회할 수 있어요. 망·방화벽 확인이 필요 없어요.
- 부서원 PC와 같은 사무실 망이라 **실제 접속 IP가 그대로 보여요**. IP 식별 문제가 없어요.

### 공유PC라서 신경 쓸 점 (계획에 반영함)
| 점검 | 대응 |
|---|---|
| 절전·재부팅 | 전원 옵션에서 절전 끄기, 서비스는 '자동(지연된 시작)'으로 등록해 재부팅 뒤 저절로 시작 |
| 서비스 계정 | 기본 `LocalSystem`. 이 계정은 **네트워크 드라이브에 쓸 수 없어요** → 백업은 로컬 폴더가 기본. NAS에 두려면 서비스 로그온 계정을 바꿔야 해요 |
| 방화벽 | `install`할 때 인바운드 8070 규칙 추가(관리자 권한) |
| 보안 프로그램 | 서명 안 된 exe를 막을 수 있음 → 처음 설치할 때 확인, 필요하면 IT에 예외 요청 |
| 포트 | 8070 (merge-master 호스트 8080·에이전트 8090과 겹치지 않음) |
| merge-master 에이전트 | 에이전트는 로그인 세션 트레이에서 돌고, 알리미는 서비스라 로그인과 관계없이 돌아요. 에이전트가 꺼져 있으면 연동만 잠시 멈춰요 |

## 1. 시작 전에 준비할 것 (내일 첫 작업 전에)

| # | 준비물 | 누가 | 필요한 단계 |
|---|---|---|---|
| R1 | **코드 저장소**: 새 GitHub 저장소(비공개 권장, 예: `buseo-alimi`). 이 클라우드 세션에서 코드를 쓰고 푸시하려면 필요해요 | 사용자 | 0단계 |
| R2 | 공유PC 정보: Windows 버전, **관리자 권한** 여부, 8070 포트 사용 가능 여부, 보안 프로그램 종류 | 사용자 | 0단계 (배포 시험) |
| R3 | **부서원 명단 엑셀 샘플**(실제 열 이름 그대로, 개인정보는 가짜로 바꿔도 됨) | 사용자 | 1단계 |
| R4 | **사내 메일 2~3개**를 복사해 붙여넣기 시험(표·이미지 포함 메일) | 사용자 | 0단계 |
| R5 | 공유PC에 merge-master 에이전트가 지금 돌고 있는지, 버전 | 사용자 | 6단계 |
| R6 | merge-master 개발자에게 요청안(설계안 5.7.1) 전달 여부 | 사용자 | 6단계 (선택) |

**개발·빌드 환경**: 개발은 이 클라우드 환경(Linux)에서 해요. SQLite 드라이버를 CGO 없는 `modernc.org/sqlite`로 쓰므로 **Linux에서 Windows용 exe를 바로 만들 수 있어요**(`GOOS=windows`). 실제 Windows 동작(서비스 등록·방화벽·붙여넣기)은 공유PC나 사용자 PC에서 확인해요.

## 3. 핵심 구현 규칙 (처음에 정해 두기)

| 주제 | 규칙 |
|---|---|
| **시간** | DB에는 유닉스 ms(정수)로 저장. 표시·D-day 계산은 `Asia/Seoul`. 마감 기본 시각 18:00 |
| **ID** | 글 id는 정수 자동 증가. 부서원은 명단의 `id`(문자열)가 키 |
| **식별 순서** | ① 서명 쿠키 → ② 접속 IP가 명단에 있음 → ③ 없으면 401 + 로그인 화면(ID 입력) |
| **개발용 사용자 흉내** | `--dev` 실행일 때만 헤더 `X-Dev-As: <id>`를 받음. 배포 빌드에서는 무시 |
| **권한 검사** | 모든 쓰기 API에서 서버가 검사: 글 수정·삭제 = 작성자 ∨ 공동 담당자 ∨ 관리자 |
| **본문 저장** | `body_format`, `body_source`(원문), `body_html`(서버가 렌더·소독한 결과). 화면은 `body_html`만 씀 |
| **HTML 소독** | bluemonday UGC 정책 + 표(`table/thead/tbody/tr/td/th`, `colspan/rowspan`), `style`은 색·굵기·정렬·테두리만 허용. `img src`는 `/uploads/`와 `data:` 금지, `http(s)`만. 링크는 `target=_blank rel=noopener` |
| **이미지** | png/jpg/gif/webp, 10MB 이하. 긴 변 1600px 넘으면 축소(gif 제외). sha256 이름으로 저장 → 같은 이미지는 한 번만. 하루 넘게 어떤 글에도 안 쓰인 파일은 정리 |
| **글 상태** | `open → done → archived`, 그리고 `trashed`(휴지통 30일) |
| **자동 상태 전이** (1분 주기) | Todo: 대상자 모두 완료 → `done` / 마감 + 7일 지남 → `done` / 글쓴이 '완료 처리' → `done`. 공지: 마감 있으면 마감 지나면 `done`, 없으면 30일 뒤 `done`. `done` + 30일 → `archived`. 일수는 설정으로 바꿈 |
| **`done`이 될 때** | ① 대상자 고정(전체 대상이면 그 시점 활성 부서원을 `post_targets`에 저장) ② `post.json` 백업 쓰기 ③ SSE 알림. 다시 열면(`open`) 고정 해제, 다음 `done`에서 같은 폴더를 덮어씀 |
| **변경 기록** | 글 생성·수정·마감 변경·대상 변경·상태 변경·삭제·응답·명단 반영을 `audit_log`에 (사람, IP, 시각, 전후 값) |
| **SSE 이벤트** | `post.changed{id}`, `post.deleted{id}`, `response.changed{postId}`, `members.changed`. 25초마다 주석 줄로 연결 유지. 화면은 받으면 해당 쿼리만 다시 불러옴 |
| **API 오류 형식** | `{ "error": { "code": "forbidden", "message": "..." } }` + HTTP 상태 코드 |
| **파일 쓰기** | 백업 JSON·설정 파일은 임시 파일에 쓰고 디스크 반영 뒤 이름 바꾸기 |

## 4. 단계별 계획

> 일수는 **개발자 한 명이 Claude Code와 함께 작업**한다고 가정한 대략적인 값이에요. 단계마다 끝나면 공유PC에 올려 실제로 확인하는 것을 원칙으로 해요.

### 0단계 — 골격·배포 경로 확보 (1.5일)
**목표**: "빈 앱"이 공유PC에서 서비스로 돌고, 다른 PC 브라우저로 열리는 것까지.

- [ ] 저장소 만들기, Go 모듈·`web/` Vite 프로젝트 초기화, prettier·gofmt·lint 설정
- [ ] `config`: `alimi.toml` 없으면 기본값으로 생성 (`port=8070`, `data_dir`, `archive_dir`, `admins`, 자동 전이 일수, `mergemaster.sources`)
- [ ] `db`: SQLite 열기(WAL, `busy_timeout`), `PRAGMA user_version` 기반 마이그레이션 실행기, `0001_init.sql`(설계안 6장 전체 테이블)
- [ ] `httpapi`: `/api/health`, 정적 파일(embed) + SPA 대체 경로, 보안 헤더(nosniff, frame DENY, CSP)
- [ ] `cmd/alimi`: `run`, `install`, `uninstall`, `version`
- [ ] `winsvc`: `kardianos/service`로 등록(자동·지연 시작, 실패 시 재시작), `netsh advfirewall`로 8070 인바운드 규칙 추가·삭제
- [ ] `scripts/build.sh`: web 빌드 → `go build` (windows/amd64, linux/amd64), 버전 정보 주입
- [ ] GitHub Actions: 태그 → `alimi.exe` + `SHA256SUMS.txt`
- [ ] **스파이크: 메일 붙여넣기** — TipTap만 있는 시험 페이지에 R4 메일을 붙여 표·서식·이미지가 어떻게 들어오는지 기록. 특히 이미지가 `cid:`·`file:///`로 오는지 확인
- [ ] **스파이크: SSE** — 공유PC 서비스 → 두 브라우저에 이벤트 전달 확인

**완료 기준**
- 공유PC에서 `alimi.exe install` → 재부팅 → 다른 PC에서 `http://<공유PC>:8070/api/health`가 `ok`
- 붙여넣기 결과를 정리하고, 이미지 처리 방안을 정함(아래 위험 W1)

### 1단계 — 사람·로그인 (1.5일)
- [ ] `members` 저장소: 목록·추가·수정·비활성
- [ ] **엑셀 가져오기 2단계 API**: `POST /api/members/import/preview`(파일 → 추가·변경·비활성·오류 목록) → `POST /api/members/import/apply`(미리보기 토큰으로 한 트랜잭션 반영)
  - 열 이름: `이름`, `id`, `IP` 필수 / `그룹`, `관리자` 선택. 열 순서는 상관없이 머리글로 찾음
  - 오류: id 중복, IP 중복, IP 형식, 이름 비어 있음 → 그 줄은 반영하지 않음
  - 명단에서 빠진 사람은 비활성(삭제 안 함)
- [ ] 빈 양식 내려받기 `GET /api/members/template.xlsx`
- [ ] `auth`: IP → 부서원, 쿠키 세션(30일, 비밀 키는 데이터 폴더에 처음 생성), `POST /api/login {id}`, `POST /api/logout`, `GET /api/me`
- [ ] 관리자 판단: 설정 `admins` ∪ 명단 `관리자` 열. **명단이 비어 있으면** 공유PC 자신(127.0.0.1)에서 접속한 사람에게 첫 설정 화면을 보여 줌
- [ ] 화면: 로그인(ID 입력), 관리 › 부서원(표 편집 + 엑셀 올리기 미리보기 대화상자), 관리 › ID로 들어온 접속 목록

**완료 기준**: 명단 엑셀을 올리고, 두 PC에서 각각 자기 이름으로 바로 들어감. 명단 밖 PC에서는 ID 입력 후 들어감.

### 2단계 — 글 등록·수정·삭제 (3.5일) ★ 가장 큼
- [ ] `posts` API: 목록·상세·생성·수정·삭제(휴지통)·복원, 마감만 변경(`PATCH /due`), 상태 변경
- [ ] 대상자: `all` / `selected` (+ 그룹 단위 선택 → 저장할 때 개인으로 펼침), 공동 담당자
- [ ] `content`: Markdown → HTML(goldmark, GFM 표·자동 링크), HTML 소독(규칙은 3장), 검색용 본문 텍스트 추출 → FTS5
- [ ] `uploads`: `POST /api/uploads`(multipart), 축소·sha256 저장, `GET /uploads/{name}`(캐시 헤더)
- [ ] 화면 — **글쓰기**(한 화면):
  - 카테고리 토글(공지·Todo), 제목, 마감(달력 + 시각, 빠른 단추: 오늘·내일·이번 주 금·다음 주 금), 대상자 선택(전체 / 이름 검색 체크 / 그룹), 공동 담당자, 링크 목록
  - 본문 탭: **서식**(TipTap: 굵게·색·목록·표·링크·이미지, 붙여넣은 이미지 자동 업로드) / **마크다운**(CodeMirror + 오른쪽 미리보기, 이미지 붙이면 `![](...)` 삽입)
  - 두 형식 사이 전환: 마크다운 → 서식은 렌더 결과로 바꿔 줌. 서식 → 마크다운은 "서식이 일부 사라질 수 있어요" 확인 뒤 변환(`turndown`) `[결정: 0단계 스파이크 뒤 확정]`
  - 브라우저 임시 저장(입력 멈춤 1초 뒤), 다시 열면 "이어서 쓸까요?"
  - Todo인데 마감이 없으면 등록 단추 비활성 + 안내
- [ ] 화면 — **글 상세**: 본문, 마감 D-day, 글쓴이·담당자, 링크, `⋯` 메뉴(수정·마감 변경·대상 변경·완료 처리·삭제), 마감 인라인 변경
- [ ] 휴지통(관리 메뉴 또는 내 글 화면): 되살리기, 30일 뒤 영구 삭제(스케줄러)
- [ ] `audit_log` 연결

**완료 기준**: R4 메일 본문을 붙여 글을 등록하면 표·서식·이미지가 유지되고, 대상자만 볼 수 있으며, 다른 사람은 수정할 수 없음(API에서 403).

### 3단계 — 목록·응답·실시간 (2일)
- [ ] 목록 API 파라미터: `view=mine|all|authored`, `category`, `pending`, `overdue`, `author`, `q`, `sort=due|created_desc|created_asc|updated`, 페이지
- [ ] **내 할 일**(기본 화면): 나를 대상으로 한 진행 중 글. 마감 지난 미완료는 맨 위 빨간 띠
- [ ] 목록 행: `[Todo]` 칩, 제목, D-day 배지(지남 빨강 / D-1 이하 주황 / 그 밖 회색), 글쓴이, Todo면 `완료 18/30`, `merge-master` 칩
- [ ] **응답**: `PUT /api/posts/{id}/response {memo}`, `DELETE`(완료 취소, `done` 전까지)
- [ ] "새 공지" 표시: 브라우저 `localStorage`에 마지막 본 시각
- [ ] `events`: SSE 허브 + `useEvents` 훅 → 쿼리 무효화
- [ ] `scheduler`: 1분 주기 자동 상태 전이(3장 규칙), 휴지통 정리, 고아 이미지 정리

**완료 기준**: A가 완료를 누르면 글쓴이 B 화면의 숫자가 새로 고침 없이 바뀜. 마감순·등록순 정렬과 필터가 맞게 동작.

### 4단계 — 대시보드 (1.5일)
- [ ] `GET /api/dashboard`: 내 카드(미완료 Todo·마감 지남·이번 주 마감), 진행 중 공지·Todo 수, 이번 주 마감 목록
- [ ] `GET /api/posts/{id}/responses`: 완료자(시각·메모) / 미응답자 (글쓴이·담당자·관리자만)
- [ ] 화면: 카드 줄, **Todo별 응답 현황 표**(응답률 막대, 마감순), Todo 상세의 완료/미응답 두 칸
- [ ] 미응답자 **이름 복사**(쉼표로 이어서), 응답 현황 **엑셀 내보내기**(`excelize`)

**완료 기준**: 요구사항 3 충족 — Todo마다 완료자·미응답자를 나눠 보고, 미응답자 이름을 메신저에 바로 붙일 수 있음.

### 5단계 — 보관·백업 (1.5일)
- [ ] `archive`: `done`이 될 때 `<archive_dir>/YYYY/MM/<id>_<제목 슬러그>/post.json` + 이미지 복사, 본문 이미지 주소를 상대 경로로 바꿔 저장 (형식은 설계안 5.6)
- [ ] 보관함 화면(읽기 전용, 검색), `⋯ → 백업 파일 다시 쓰기`
- [ ] 되살리기: 관리 › `post.json` 올리기(같은 폴더의 이미지도 함께 — 폴더를 zip으로 올리거나 이미지 여러 개 선택)
- [ ] 매일 03:00 `VACUUM INTO backups/alimi-YYYYMMDD.db`, 14개 보관. `alimi.exe backup`으로 즉시 실행
- [ ] 업그레이드 안전망: 마이그레이션 실행 전 DB 사본 자동 생성

**완료 기준**: 글을 완료 처리하면 폴더가 생기고, DB를 지운 새 설치에서 `post.json`을 올려 그 글이 되살아남.

### 6단계 — 시범 운영 (1일 + 1주 사용)
- [ ] 공유PC 배포 절차서(README) 작성, 실제 설치
- [ ] 부서원 몇 명과 1주 시범 사용 → 불편 사항 수집·수정
- [ ] 부하 확인(가볍게): 60명이 동시에 SSE 연결 + 목록 새로 고침 → 응답 시간 확인

**완료 기준**: 시범 사용자의 등록·응답·대시보드 흐름에서 막히는 곳 없음 → **1차 정식 오픈**

### 7단계 — merge-master 연동 (1.5일, 선택)
- [ ] `mergemaster` 수집기: 5분마다 `sources` 조회 (기본: `http://127.0.0.1:8090` — 같은 PC 에이전트). 부서원 PC `:8080` 훑기는 설정으로만 켬(기본 끔)
- [ ] 업무마다 `GET /api/session?s=<slug>`로 `job` 확인 → 키 `주소 + slug + job`
- [ ] 새 업무 → Todo 자동 등록: 제목 `[엑셀 취합] {title}`, 본문 `description` + 취합 주소 링크, 마감 `deadline`(호스트 현지 시각 문자열 → KST로 해석), 글쓴이 = `requester`와 이름이 같은 부서원(동명이인·없음이면 '시스템'), 대상 전체
- [ ] **링크 주소**: 127.0.0.1로 조회해도 글에 넣는 주소는 공유PC의 LAN 주소(설정 `public_host`)로 바꿔 넣음
- [ ] `closed` 또는 업무가 사라짐 → 그 글을 `done`. 마감이 바뀌면 글 마감도 갱신(글쓴이가 손으로 바꾼 뒤에는 덮어쓰지 않음)
- [ ] 관리 화면: 조회 대상 목록·마지막 성공 시각·오류
- [ ] 가짜 merge-master 서버로 테스트(목록 → 등록, 같은 업무 다시 → 중복 없음, closed → done)
- [ ] (요청 1이 반영되면) 사람별 완료 자동 표시

**완료 기준**: 공유PC 에이전트에서 merge-master 업무를 시작하면 5분 안에 알리미에 Todo가 생기고, 마감 저장 뒤 완료로 바뀜.

### 8단계 — 알림 발송 (사내 API 준비되면)
- [ ] `notifications` 대기열 + `Notifier` 인터페이스, web 어댑터(화면 알림 종)
- [ ] 메신저·메일 어댑터, 발송 시점(새 글 / D-1 / 당일 오전 / 마감 지남), 실패 재시도
- [ ] 대시보드 `미응답자에게 알림` 단추

## 8. 내일(1일차) 할 일

1. **R1 저장소 만들기** → 이 세션에 연결(또는 새 세션에서 그 저장소로 시작)
2. 0단계 골격: Go 모듈 + Vite 프로젝트 + `/api/health` + embed + `run` 명령 → Linux에서 실행 확인
3. SQLite 마이그레이션 실행기 + `0001_init.sql`
4. Windows exe 크로스 빌드 → **사용자가 공유PC에서 `alimi.exe run`으로 실행**해 다른 PC에서 열리는지 확인 (R2)
5. TipTap 붙여넣기 시험 페이지 → **사용자가 R4 메일을 붙여 결과 공유**
6. 가능하면 `install`(서비스 등록·방화벽)까지

**1일차 끝 상태**: 공유PC에서 빈 알리미가 열리고, 메일 붙여넣기 결과를 보고 2단계 에디터 방식을 확정할 수 있음.
